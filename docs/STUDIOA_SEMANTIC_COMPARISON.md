# StudioA 新版語意資料受控比較

2026-09-16。這輪比較資料修訂整體是否改善 Stage1 對保留 AI 像素的學習；
不將訓練完成或標籤一致率當成整店 3D／顧客分析的驗收。

## 訓練前固定的方案

| 項目 | 對照 | 候選 |
| --- | --- | --- |
| train 來源 | `studioa_partial_supervision_20260916_v2`，46 張 | `studioa_semantic_ready_20260916_v1`，62 張 |
| val 來源 | 共用 `studioa_semantic_ready_20260916_v1` 的 33 張 | 相同 |
| 更新預算 | 495 次，45 epochs | 495 次，33 epochs |
| 選模時點 | 初始化及第 165／330／495 次更新 | 相同 |
| 選模依據 | 全部 19 類 source-val scene mIoU | 相同 |

兩組使用 ResNet18 ImageNet 骨幹、64 通道 FPN、19 類 scene head、512×896
輸入、batch 4、seed 42、AdamW、lr 0.0002、相同增強與初始化。
共用舊版 46 張 **train** 計算的類別權重，驗證像素不參與權重計算。
固定 deterministic 模式、停用 TF32 與 early stopping；完成後逐張量核對
`initial_state.pt`，並核對兩組實際更新數、驗證時點與評估輸入雜湊。

候選同時增加影格與修訂標籤，因此結論只針對整份資料修訂，不能單獨歸因於
多出的 16 張或某一類補標。單一 seed 是先導比較，不提供統計穩定性結論。

## 隔離與保存

`studioa_train.py prepare --scene-validation-source` 將驗證來源另行凍結，
只允許相同 source-val 影格、相機與影像內容；訓練資料只由各自的 train 來源提供。
現有 Trainer 的 validation-only 設定與跨資料集鏡頭洩漏檢查繼續生效。
兩組不建立 test loader，不執行 test 推論，不依 test 結果調參。

工作根目錄：`runs/studioa_semantic_comparison_20260916_v2/`。
每組保存程式／設定／資料／權重雜湊、持久服務 log、status、初始／best／last
權重及 baseline／validation 報告。工作由 systemd user service 依序執行，
完成後才檢查結果；SSH／編輯器斷線不會停止。

## 結果判讀規則

共同新版 val 的 19 類 mIoU、每類 IoU 與差值全部呈現，另外明列柱子、門、
固定玻璃、手機、消防設備；同時指出其他類是否退步。玻璃 val 僅一個相機，
重複影格不是獨立場景，已揭露 AI 標籤不是獨立真值。

這輪不自動替換既有模型。若整體上升但弱類未改善，下一步仍須針對失敗類型
檢查標註、解析度與採樣；不能只憑整體均值宣稱資料已足夠。

## 執行狀態

方案已固定；工具的獨立驗證來源、真實 CPU 訓練路徑與相關資料／完整性檢查
共 58 項測試通過。共用 backend 修正後的相關 CPU 回歸 89 項通過、2 項因 CUDA
條件跳過；GPU／精度檢查另有 17 項通過。Ruff、工具 ty 及提交型別門檻通過。
直接檢查 seeding.py 仍有既存的 PyTorch `Module.to(memory_format=...)` 型別診斷，
既有型別門檻確認未增加診斷；沒有藉本輪修改忽略規則。

第一批 v1 已完成，但檢查時發現 deterministic 分支提前返回，未套用設定中的
TF32 開關。此批結果只保留歷史診斷，不作最終比較。修正 `72081e7` 將精度設定
移到分支之前，回歸測試先重現兩個失敗，再驗證修復。v2 從頭重跑兩組，並在
訓練開始前核對／保存 `backend.json`：matmul 與 cuDNN TF32 均為 false。

PyTorch deterministic 模式仍為 warn-only；CUDA cross-entropy 會提示沒有
完全決定性的 kernel，因此不能宣稱逐 bit 重現。兩組初始張量與未訓練 val
結果另行直接比對，不能只依賴相同 seed。

## 最終結果與處置

v2 兩組及診斷服務均退出 0。完整 CPU 回歸 **4,185 通過、12 項因 CUDA 條件跳過**。
受測與訓練程式 commit `72081e7`；未推送，GitHub Actions 由使用者另行確認。

- 對照：45 epochs／495 更新，選中第 495 次更新，mIoU **25.6063%**。
- 候選：33 epochs／495 更新，選中第 330 次更新，mIoU **25.6387%**。
- 差值僅 **+0.0323 個百分點**，不構成有意義或穩定改善的證據。
- 194 個初始 state 張量逐一相等，初始化 val 結果完全相同；驗證支援像素一致。
- 兩組共 2,227 個凍結輸入逐檔核對通過，所有 checkpoint 張量有限、job 綁定正確。
- 未執行 test、未替換既有保留模型；候選存為診斷參考。

### 弱類診斷

以下混淆只計入新版 source-val 已標註像素，不是完整影像的精確率／召回率。
用相同凍結模型重新計算的混淆矩陣與正式逐類 IoU 一致。

- **柱子**：候選仍有 93.33% 柱子像素判為 wall。train 正例仍是 10 張／2 相機，
  新增 val 正例讓缺口可測量，並沒有增加柱子的訓練視角。
- **手機**：train 正例已從 6 張／3 相機增至 12 張／4 相機，但只占縮放後有效
  train 像素的 0.119%；val 手機像素 64.30% 被判為展示桌、21.16% 為海報、
  13.09% 為櫃檯。增加正例數仍未解決與周圍設施的混淆。
- **消防設備**：train 正例 8→11 張，但仍只有 2 個相機；val 約 65.29% 被判為
  person、24.90% 為 display_cabinet。
- **海報**：train 正例從 4 張／3 相機增至 16 張／7 相機。val 正例像素召回
  57.42%→77.82%，但已標註區域的假陽性 9,502→146,814，像素精確率
  71.34%→17.92%；主要錯在牆與展示桌。這次退步不是「完全不認海報」，而是
  過度預測海報；不能單靠加更多海報正例解決。

### 接續順序

1. 在 **train** 檢視海報與牆／展示桌的混淆、柱子外觀差異，核對可用的正確對照區域。
   val 只用來診斷；不把該鏡頭搬入 train，也不將未知像素當負例。
2. 凍結小物件／弱類取樣方案，讓手機、消防與柱子得到有效訊號，同時保留大場景上下文。
   再做單一變因比較，檢查海報假陽性與展示桌／櫃退步是否改善。
3. 若 train 缺少需要的外觀或相機，再由 GCS 定向取資料並由 AI 補標；不以單純張數當充分性。
   Stage1 未通過前，Stage2–4 不標成已完成。
