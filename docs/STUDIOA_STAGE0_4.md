# STUDIO A 新店部署目標與本輪訓練

> 2026-09-16 更新：本頁保留先前分工與實驗記錄。本次使用者指定 Stage1 為場景理解；
> 最新目標、逐類能力差距與 Stage 對照見 [分類與階段核對](STUDIOA_CAPABILITY_AUDIT.md)。

2026-09-12。目標是讓新店從攝影機畫面建立可驗證的空間，再持續產出各區域的人員
屬性熱點與行為資訊。以下 Stage0–4 是這個產品目標的分工；README 原有三段式操作
流程仍是現有工具的使用方式，不能把新分工視為五階段都已完成。

| 階段 | 給下一階段的資料 | 目前可沿用 | 新店驗收仍需完成 |
|---|---|---|---|
| Stage0 空間建置 | camera/calibration、可行走地面、牆柱、設施實例、區域、來源版本與有效範圍 | `commission_camera.py`、場景建模、九鏡頭候選與 GLB 回投影報告 | 整店留出分割；門窗邊界；獨立尺度檢核；每個物件的支撐面、方向與未確定狀態 |
| Stage1 人員追蹤 | 帶時間、camera ID、track ID、位置及座標版本的 WorldFrame | 偵測、追蹤、`CameraState.world_frame` | 真實新店的遮擋、追蹤斷裂、腳點定位；離線與服務輸入解析度一致性；掉幀時間處理 |
| Stage2 屬性與熱點 | 每條軌跡的員工/顧客/unknown、姿態與可用外觀屬性；每區人數、停留人秒、流向 | 人員 crop/屬性模組、staff 門檻、離線 heatmap/flow 工具 | 屬性整店留出；服務端增量網格彙整；unknown 獨立統計；重疊鏡頭去重或明示分鏡頭統計 |
| Stage3 行為事件 | 進出、停留、排隊或受限區域事件，附規則依據、位置、時間及片段索引 | `CameraAlerts → ZoneMonitor → record_alert` 已接入 pilot | 新店政策與人工事件對照；事件 precision/recall、每小時誤報；取放等行為不得只憑單張姿態下結論 |
| Stage4 即時介面與歷史分析 | 可切換區域/時間/屬性的熱點、行為列表、趨勢與事件回看 | 現有報表與 dispositions 記錄 | 常駐服務、更新延遲與健康狀態、斷線恢復、資料留存；代表性新店多鏡頭連續驗收 |

空間中一個影像點只決定一條射線；支撐平面提供交點，實際長度約束尺度。因此，
分割分數提高不等於公尺座標更準。新店流程應自動產生場景候選、顯示缺少的量測或
不確定區域，再形成可追溯的 commissioning bundle；目前不能承諾完全不需現場約束。

熱點要區分「此刻人數」和「一段時間累積的停留人秒」，不能直接拿影格計數比較
不同掉幀率的鏡頭。屬性須帶模型版本、觀測量與 unknown；跨鏡頭身份尚未驗證時，
同一個人不可被報成已去重的全店獨立訪客。即時性須量測攝影機時間到介面更新的
延遲、處理影格率、掉幀率與連續運行穩定度，單獨的 GPU FPS 不能代替這些指標。

## 六小時背景工作

執行程式為 `tools/commissioning/stage0_train.py`。本輪輸出目錄
`runs/stage0_cross_store_20260912_v2/`，絕對截止為台灣時間 **2026-09-12 16:25**。

1. 凍結 batch02、batch03 與 site30k 的分割樣本。site30k 每鏡頭每日最多取四張，
   均勻跨越該日樣本；保留來源標註、映射方式、影像內容及檔案 SHA256。
2. Kaohsiung、Taichung、Tao-Hsin 輪流整店留出。來源店沿用原 train/val 鏡頭分組，
   原 test 鏡頭不參與擬合或選模；目標店所有保留影格只作 test。同鏡頭或相同影像
   內容跨分區即拒絕。ADE20K 固定取 512 train、64 val 作一般室內監督。
3. 六組新訓練：三個店別各做 standard、photometric。兩組使用相同種子 42、
   ImageNet RegNet-X-800MF 初始權重、512×896 輸入與資料；後者只提高亮度、對比及
   飽和度增強。六類為 void、floor、wall、column、fixture、person，void 不受監督。
   只訓練 terrain head，以來源店 validation 的 `terrain_mIoU/site_seg` 選模。
   每組最多 40 epochs、40 分鐘，validation 八次未改善即停；保留 best/last。
4. 每組完成後才評估該留出店，記錄逐類別 IoU、像素支援量及 checkpoint SHA256。
   三店完成才計算等權平均與最差店；逾時候選標為 partial，不能混入完成組平均。
   單種子結果屬探索性對照，不能宣稱統計上穩定優於另一組。
5. 若剩餘時間足夠，再訓練員工/顧客探針：使用人工分類 crop，同一 track 合成一筆，
   整店留出，標準化只看來源店。比較 torso colour 與 colour + ImageNet frozen stem，
   保存逐店、逐鏡頭、逐 track 結果及候選權重；不解除既有相機驗證與 unknown 門檻。

背景 worker 使用獨立 systemd user service，不依賴本對話存活。訓練及評估逐一使用
GPU，每步都有逾時、程序群組清理與日誌，`status.json`、`REPORT.zh-TW.md` 每十秒
更新。結束時再驗證凍結資料，失敗與未執行項目不寫成成功。候選保留在 runs 下；
現有 checkout 尚有未提交程式，因此訓練明確使用 `--allow-dirty`，凍結原始碼提供
重現依據，這些實驗尚不是可發佈 bundle。

## 結果不能跨越的界線與下一步

現有門市分割多為教師模型標註；分數代表教師一致性。六類映射將桌架/商品合併為
fixture，且舊標註把玻璃門併入 wall。這輪不能建立玻璃門準確率，也不能提供每張桌
每個架子的實例身份、實測尺度或完整 Stage1–4 的新店準確率。

下一個接入點是把通過留出店檢查的 student 分割作為 Stage0 自動候選來源，接入原有
平面/實例/支撐面及 GLB 回投影驗收；不直接用 dense label 覆蓋已審核的門、區域或尺度。
同時依 PLAN §10.10 的 S0-02/03/05 補足門窗控制、獨立量測及跨店人工標註。之後固定
一套新店影片與區域規則，沿 Stage1–4 做座標、屬性、熱點、事件、時間延遲的一次完整
回放及常駐服務驗收，才有依據宣稱「未來新店可直接使用」。
