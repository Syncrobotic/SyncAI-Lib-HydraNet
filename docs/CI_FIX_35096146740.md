# CI 35096146740：可選標註套件的測試隔離修正

使用者指出的 [Python 3.11 失敗工作](https://github.com/Syncrobotic/SyncAI-Lib-HydraNet/actions/runs/35096146740/job/104793875612)
受測 commit 是 `db95e6f`。整輪後來被取消，但這個 job 確實已失敗，原因不是取消。
後續 [35098293546](https://github.com/Syncrobotic/SyncAI-Lib-HydraNet/actions/runs/35098293546)
在 `20e6b2d` 的 Python 3.11／3.12／3.13 都出現同一失敗，其餘六個工作通過。

## 根因與修正

`test_worker_freezes_writes_resumes_and_rejects_foreign_checkpoints` 使用假的 SAM3
與視覺 reviewer，但 worker 寫入 `environment.json` 時仍查詢真的
`importlib.metadata.version("transformers")`。CI 安裝 `dev + export`，沒有
`annotate` extra，因此觸發 `PackageNotFoundError`。

先前乾淨副本沿用工作站 venv，仍含 transformers；它驗證了沒有私有資料的情況，
沒有驗證缺少可選套件的情況。先前本機通過不能代表這個 CI 環境也通過。

修正 commit `cd13982` 只改測試：將假 teacher 的版本 metadata 一併替換為
`test-double`，並核對初次標註及 relabel 的環境紀錄。其餘必要套件仍查真實版本。
worker 的凍結、續跑、拒絕外來 checkpoint、來源雜湊等檢查繼續執行。
未新增套件、跳過測試、降低門檻或修改正式 worker 的版本記錄行為。

## 驗證

在 `/tmp/hydranet-ci-35096146740` 建立沒有私有資料的副本，每個 Python 使用獨立
venv，執行 `uv sync --locked --group dev --extra export`。先以未修正程式重現
同一個 `PackageNotFoundError`，修正後該測試檔 10 項通過。
三個環境均核對 transformers 不存在，且各自安裝 94 個 distribution。

| Python 實測版本 | 通過 | 跳過 | src 覆蓋率 | scripts/tools 覆蓋率 |
| --- | ---: | ---: | ---: | ---: |
| 3.11.15 | 4,160 | 24 | 87.19% | 12.27% |
| 3.12.13 | 4,160 | 24 | 87.19% | 12.27% |
| 3.13.15 | 4,160 | 24 | 87.19% | 12.27% |

使用正式 `scripts/coverage_ratchet.sh`，覆蓋率門檻仍為 src 85%、scripts/tools 11%，
跳過上限仍為 25。每次保存 JUnit、coverage JSON、套件清單、受測 commit 與日誌。
[機器可讀紀錄](reviews/ci_fix_35096146740.json)；原始輸出在本機
`runs/ci_fix_35096146740/`，不隨 Git 發布。

本機 `.python-version` 為 3.11。最初兩個高版本驗證工作因未將 `UV_PYTHON` 傳給
後續 `uv run` 而重建成 3.11，已停止且不採計；最終工作明確固定解譯器並重新
核對實際版本。環境重現步驟已加入 [CONTRIBUTING](../CONTRIBUTING.md)。

這是本機完整單元測試矩陣，並非新的遠端 CI；Python patch 版本以表列實測為準。
本輪沒有重新執行遠端 export／security 工作，也沒有推送。
查詢時遠端 dev 仍為 `20e6b2d`，尚未包含 `cd13982`；需在包含修正的版本上
重新觸發 GitHub Actions，才能確認遠端綠燈。
