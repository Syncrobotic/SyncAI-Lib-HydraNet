## 已確認的整合缺陷

1. 同一 Kaohsiung 來源影像及相機設定，原 commissioning 證據的 `store_axis` 為
   55.2139°，student 候選證據變成 39.0275°。全店方向仍依賴分類遮罩／深度區域的
   fallback 投票，新增分類會改變全局方向。差值 16.1864° 是兩份模型估計之差，
   不能當成對真值的角度誤差，也不能據此認定原方向一定正確。
2. 新輸入轉換器保留 object ID 分區，卻省略既有 `instances.npz` 及 `support_tops.npz`。
   Kaohsiung 的兩項來源實際存在，候選端不存在，`scene.supports.json` 是空陣列。
   原桌面／支撐細化路徑因此無法執行。修正時必須重新綁定實例及來源，不能直接
   複製舊 ID 對應的約束到新 ID。
3. 五份 `scene.surfaces.json` 的 `fixtures.gate_d_status` 都是 `not_evaluated`。
   初步擬合分數、檔案存在與有限頂點檢查沒有檢驗最後匯出物件的方向、尺寸、位置。
   該流程仍允許未檢驗幾何進入總覽圖。

Kaohsiung 最終 `display_table_4` 的模型參數約 1.7938 × 0.8415 × 0.7658 m；
原圖回投影顯示其檯面邊線、櫃體底部與可見輪廓不相合。這些數字是輸出模型尺寸，
不是現場櫃體的實測尺寸。

## 修正順序

先固定並核對房間方向與每件設施的幾何依據，恢復經來源與實例重綁定的桌面／支撐
約束；新模型分類不得默默重估整間店的姿態。從 Kaohsiung 中間長櫃開始，以最終 GLB
投回原圖比較檯面邊線、接地位置、遮擋關係及朝向，通過後再逐鏡頭推進。

必須保留拒收狀態，直到最終物件幾何檢查及視覺覆核均完成；既有訓練分數或單元測試
通過不能代替這個條件。原 commissioning 輸入的來源雜湊已重新核對，五鏡頭均未被改動。
