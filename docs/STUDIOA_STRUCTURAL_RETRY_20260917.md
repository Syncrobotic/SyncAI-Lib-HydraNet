# Stage0 自動補觀測與有界重試

2026-09-17。接續[表面與條件方向流程](STUDIOA_STRUCTURE_AUTONOMY_20260917.md)，
既有 `structural_observe.py` 入口增加 `--retry`，可從單一固定相機的影片目錄自動補觀測。
這完成資料取得與停止規則；尚未完成陌生場域的幾何驗收，也不輸出部署用 camera.json。

```bash
HF_HUB_OFFLINE=1 TRANSFORMERS_OFFLINE=1 .venv/bin/python \
  tools/commissioning/structural_observe.py CAMERA_ID /path/to/camera-videos \
  --retry --max-attempts 3 --frames-per-window 3 --device cpu \
  --out /path/to/new-report.json
```

沿用既有 `commission`、`annotate` extras 與固定 SAM 3 權重；影片解碼另需 PATH 上的
`ffmpeg`／`ffprobe`。輸出旁的 `.retry/` 目錄保存狀態、來源計畫、逐次觀測及最終線組。
新場域不需要舊資料；接續已完成的自動觀測時，可同時指定 `--seed-surfaces` 與
`--seed-groups`，繼承來源綁定的表面報告及凍結分組。這兩項不得使用 commissioned 幾何。
已有報告或 evidence 目錄會拒絕覆蓋。CLI 執行錯誤回傳 1；拒絕、證據不足或分組衝突
屬於已完成的診斷決策，回傳 0，使用者須讀取 JSON 的能力狀態，不能把 exit 0 當校正通過。

## 固定策略與停止規則

- 在讀取新觀測分數前，按檔名順序凍結影片清單及 SHA-256。StudioA archive 名稱包含時段，
  其他檔名只提供固定順序，時段未知。不遞迴掃描多相機資料，也不按 camera ID 改策略。
- 預設最多 3 次，包含可選的舊觀測評估；因此繼承舊資料後最多再取 2 段影片。
  可設定 1–8 次、每段 2–6 張。預設每段在時長的 10%、50%、90% 請求解碼原始 PNG。
  記錄的是請求時間偏移，並非聲稱取得精確來源 PTS。
- 影片在解碼前後核對雜湊，影格核對原始尺寸。旋轉、非正方形像素或無效時長會拒絕。
  ffprobe／單次 ffmpeg 分別有 30／60 秒上限；這不是整個 CLI 的總時間上限。
- 同內容影片只取一次；跨時段、含舊資料的相同 RGB 像素不重複計票。少於兩張唯一影格
  的時段記錄不足並消耗一次額度。
- 沿用固定 SAM 3 版本、提示、門檻及既有弱邊緣追蹤器。舊資料會核對模型策略、
  原始影格與遮罩雜湊、相機／尺寸契約，以及分組對表面報告的內容綁定。
- 只有明列的方向支持或覆蓋不足，且尚無完整 `line_checks` 時，才允許下一次取得資料。
  已完成幾何檢查後，通過或拒絕都結束；未知原因與執行錯誤也不會無限制重試。

## 跨時段線組帳本

舊線組的 ID、擬合／留出側、代表像素和地板提示固定不變。新觀測若可由既有同一
division 曲線解釋，只增加來源時段，不增加獨立線票數，也不以更有利的像素替換舊觀測。
新線組只分配一次擬合／留出側，且在執行方向求解前封存帳本。

新候選若同時可配到多個既有線組，整次合併拒絕，停止於 `partition_conflict`，保留舊帳本。
無論那些線原本在同側或異側，都不能任選一組、移動分組或只保留有利部分。
這是保守的幾何相容檢查；仍不能證明所有候選都對應正確的實體線，漏合併或誤合併
仍是待評估風險。多時段固定 CCTV 沒有增加三角測量視差。
